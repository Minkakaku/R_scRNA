# 新项目接入规范

实际项目只在 `/workspace/projects/<项目名>/` 创建一次，R/Python 共用项目根目录；目录与配置规则见 `/workspace/AGENTS.md`。

1. 创建项目时建立 `logs/README.md` 总记录，填写项目目标与概况；确定输入、样本、分组、物种、参考资源和拟使用的分析方法，统一维护项目样本表、人工注释及配色。后续所有操作均按时间追加到总记录。
2. 先适配所调用公共库的加载器与步骤入口，显式传入项目目录、代码库根目录和共用配置；项目相对路径不依赖 shell 当前目录。
3. 建立仅使用本地独立 Git 仓库的统一项目模板，不创建或推送实际项目 GitHub 仓库；按需从 GitHub 以子模块获取公共库到项目 `deps/` 并固定提交；`workflow/` 按分析顺序使用编号 `.R`、`.py` 短脚本，调用对应公共库；代码仓库路径、版本与各步骤运行环境记录在项目配置或说明中。
4. 验证配置覆盖、R/Python 共用元数据、输入输出路径、跨语言转换及从不同当前目录启动的结果。只检查配置或 dry-run 不代表真实生物学分析已验证。
5. 验证通过后迁移实际项目，保留已运行脚本、历史输出、来源与人工决策。`results/` 的编号固定对应分析点，由项目配置维护；同一分析点重跑、调整参数或补图仍使用原目录并更新对应产物，不按运行次数新增结果目录。仅新增分析点时分配新的结果编号。运行批次、参数与代码版本追加到 `logs/README.md`，原始运行日志另存 `logs/`。

当前仓库内 `projects/project1/` 是未运行的兼容示例，加载器仍假定项目位于仓库内部。直接复制或搬到集中项目目录不能完成上述接入。环境使用现有 R、默认 Python 与 pySCENIC 兼容环境；每个新 shell 先加载 `/workspace/.onboarding/env.sh`。

恢复已有项目获取其记录的子模块提交；不在每次分析前自动拉取最新版。依赖升级单独核对、验证并更新项目提交指针。项目还需记录精确环境版本，实际运行入口指向本项目依赖代码。

每个项目在 `logs/README.md` 维护唯一的项目总记录，汇总项目概况并按时间追加所有操作，包括检查、依赖与代码变更、参数调整、人工决策、运行、失败、重跑和结果核对；每条注明时间与时区、目的、脚本或命令、输入与参数、代码和环境版本、状态、日志及固定结果路径。根目录 README 作为入口和运行索引，链接到总记录。总记录纳入项目本地 Git，原始运行日志忽略；项目内容不上传 GitHub。
